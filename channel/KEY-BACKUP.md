# 频道私钥的加密备份（灾难恢复用）

- **公钥**（可以公开）：`YXoAcwa3clZCRd7+DlIHMS3cQ40HlyXVSKblvX5Ye1M=`
- **指纹**：`ed25519:06:d0:c4:4d:29:1c:ef:66`
- **加密备份**：`channel-key-backup.enc`（AES-256-CBC + PBKDF2 600k 迭代）

## 为什么备份是加密的

私钥是频道体系的**信任根**：拿到它的人能签出"你的"频道，让用户装下任意层文件。
所以明文私钥**永不进仓库**（`.gitignore` 已挡 `*.key` / `*.pem` / `.sunsetlinux-keys/`）。
但容器/机器可能丢、人可能忘 —— 于是留一份**加密**副本在仓库里：没有口令，它只是随机字节。

## 怎么解密（在你自己信任的机器上）

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -iter 600000 \
  -in channel-key-backup.enc -out channel.key
chmod 600 channel.key
# 解出来后**先核对指纹**（应为 ed25519:06:d0:c4:4d:29:1c:ef:66）：
node tools/channel/pub-of.mjs --key channel.key 2>&1 | grep 指纹
```

口令存在你的密码管理器里。**口令丢了 = 这份备份废了**，但频道不会立刻坏
（CI 的 Secret 里还有一份可以继续签名）。

## 这份备份能给什么、不能给什么

| | |
|---|---|
| ✅ 能给 | 私钥丢失时恢复签名能力（Secret 被误删 / 本机磁盘坏了 / 容器被删） |
| ❌ 不能给 | **完整性**保证。加密不认证（CBC 没有 MAC），备份文件本身可能被替换 —— 所以判断"是不是原配"永远看**指纹**，不看文件 |
| ⚠️ 注意 | 仓库是**公开**的。任何人拿到这个文件都能离线爆破口令，所以口令必须是高熵随机串（当前是 32 字符随机串），**不要**改成人类可记的短口令 |

## 什么时候该轮换密钥

目前**还没有任何用户**，所以现在轮换的代价最低。真要轮换时：

1. `keygen` 生成新密钥对；
2. 用新私钥重新签 `channel.json`（`sign.mjs`）；
3. 把**新公钥 + 新指纹**发出去，并明确说明"签名者已更换"；
4. 旧公钥作废：让用户删掉旧频道配置（留着只会一直验签失败）。

> 判断标准：**用户手里的指纹**才是一切。公钥与指纹必须通过另一个渠道（不跟清单同一处）送达。
